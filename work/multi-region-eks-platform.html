03 · Platform Engineering

Multi-Region EKS Platform at Scale

Full lifecycle ownership of 30+ production clusters, changed without downtime.

  • 30+EKS clusters, multi-region
  • 100+engineering teams served
  • Zerodowntime infrastructure changes

Problem

Thirty-plus production Kubernetes clusters across multiple AWS regions, serving 100+ engineering teams who ship continuously. Any platform change — a Kubernetes version bump, a CNI upgrade, an add-on rollout — is simultaneously a change to every team's production environment. A bad rollout doesn't break one service; it breaks the company.

Approach

A wave-based rollout strategy: changes propagate through defined cluster tiers with bake time and health verification between waves, so a regression surfaces in a low-stakes wave long before it reaches revenue-critical clusters. Terraform as the single source of truth across the fleet, enforcing cloud security standards and SOX-compliant governance uniformly rather than cluster by cluster. A core platform stack of Cilium for networking, Istio for service mesh, and ArgoCD for GitOps-driven delivery, with Karpenter handling node provisioning across the fleet.

Impact

Zero-downtime infrastructure changes across the production fleet, and 100+ teams shipping without having to think about the platform beneath them — which is the entire point of the job.
